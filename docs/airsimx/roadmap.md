# AirsimX 迭代路线图

状态日期：2026-11-06。这是实施规划，不是发布公告。版本号表示建议里程碑，不承诺发布日期。版本状态见[兼容性矩阵](compatibility.md)。

## 项目边界

面向无人机仿真、算法验证和数据采集，先维护可复现的多旋翼闭环。品牌改名、引擎迁移、飞控升级和算法适配分开实施。初期保留 `AirSim` UE 模块名、`import airsim`、RPC 接口及配置字段。

## M0：可复现基线

已完成开发准备、项目内 Eigen 3.3.7/rpclib 2.3.0 下载及摘要记录；Windows x64 Release/Debug 的 rpclib、MavLinkCom、AirLib 与 AirLibUnitTests 均已构建成功。

原始测试的日期解析、车辆初始化、无限循环等问题已修复，并补充了有效断言、墙钟看门狗和路径完成判定；两种配置下 22 项验证通过，详见[验证记录](core-validation.md)。M0 尚未完成，后续需要：

- 将本地依赖准备整理成可版本管理、可跨机器复现的流程，复核第三方许可与依赖锁定。
- 建立旧版或可追溯参考环境的飞行与传感器回归记录。
- 将依赖准备与构建分离，避免自动安装、交互提示及意外覆盖资产。
- 将核心库测试与需要 Unreal 的集成测试分层；引擎集成测试使用具备授权引擎和必要 GPU 的执行环境。

验收：从干净检出按文档重建核心库，测试有明确退出码，日志记录源码提交、依赖和工具链版本。编译器冒烟通过不能替代这一验收。

## M1 / v0.1：UE5 多旋翼最小闭环

范围：Windows、一个锁定的 UE5 版本、Blocks 场景、单架多旋翼、SimpleFlight、核心 Python API。

工作重点：

- 试编译后选择 UE5 精确小版本与匹配的 MSVC/SDK，不宣称支持所有 UE5 版本。
- 迁移构建规则、废弃接口及插件依赖；隔离汽车相关 PhysX 代码与资源。
- 保留并验证 AirLib 多旋翼动力学，不顺便整体重写为 Chaos。
- 审计 Unreal 碰撞、物理和 AirLib 更新的职责边界与时间同步。
- 检查 UE 双精度坐标、AirLib 数值类型、厘米/米及坐标系转换。
- 验证 RGB、深度、IMU、GPS；检查分割和其他输出的迁移影响。
- 验证编辑器运行和打包后运行，不仅验证工程能打开。

建议验收门槛，实施时应冻结配置与阈值：

- 自动完成连接、解锁、起飞、悬停、移动、降落。
- 无风固定场景悬停 60 秒，记录位置/姿态误差，无 NaN 或失控。
- RGB/深度输出尺寸、数值范围正确；传感器时间戳在单次运行内符合约定。
- 连续执行 20 次重置及短任务，无崩溃或持续增长的连接泄漏。
- 在声明的硬件与画质下记录帧率、实时因子、采集耗时；不预先承诺固定性能。

不纳入 v0.1：汽车完整迁移、Unity、HITL、全平台、大规模多机或大量算法集成。

## M2 / v0.2：现代飞控

顺序：PX4 SITL，再 ArduPilot SITL；HITL 单独安排。候选版本不等于兼容承诺。

- 明确仿真传感器/执行器链路与高层控制链路的区别。
- 验证机型配置、参数、启动方式、坐标系、仿真时钟和 lockstep。
- 验证 Offboard/Guided 模式、解锁条件、失效保护和连接恢复。
- 为 PX4 与 ArduPilot 分别列出可用控制 API；后者当前存在未实现接口。
- 先测试单机，再隔离多机端口、身份和状态。
- 仿真配置与实机配置分开，不向实机复制禁用失效保护的参数。

验收：每个声明支持的版本完成起飞、悬停、位置/速度任务、降落、断连处理和重启恢复，保留飞控日志与仿真日志。仅收到心跳不算通过。

## M3 / v0.3：算法接口与评测

优先建设 Python SDK、ROS 2 bridge、Gymnasium 适配层，不把算法依赖塞入仿真核心。

- 统一时间戳、相机标定、坐标系、传感器同步和 reset 语义。
- 为定位、规划、避障、强化学习逐类提供版本固定的最小示例。
- 明确观测、动作、奖励、终止条件及随机种子控制范围。
- 记录成功率、碰撞率、轨迹误差、任务耗时与运行配置。
- 区分可复现实验与逐位确定性，不承诺跨硬件完全相同结果。

验收：算法在独立进程或环境中通过公开接口运行；至少一个端到端示例可重复执行并产生评测结果。

## 决策与推进规则

当前推荐 Windows 运行 Unreal，独立 Ubuntu 24.04 环境承载飞控和 ROS 2 候选组合。现有 Ubuntu 26.04 保持不变；安装新发行版是后续环境准备工作。

UE5 精确版本仍待工具链匹配检查与迁移试编译。依赖更新、Python 兼容性与 ROS 2 适配各自留测试证据；每完成一次验证，同步更新兼容性矩阵。大版本迁移前保留原始场景副本，不对唯一资产副本直接转换。
